chrome-devtools 분리/복구 운영 문서 (반복 방지용)
작성일: 2026-05-28 KST

목적

- 전역 `--isolated=true` 때문에 LLM 세션마다 Chrome/DevTools가 새로 생기는 문제를 막는다.
- workspace별로 고정 Chrome debug browser를 하나씩 두고, Codex/LLM CLI는 `--browser-url`로 그 브라우저에 붙인다.
- PID는 MCP 연결 대상이 아니라 “어떤 Chrome/CLI 프로세스를 관리할지 식별하는 키”로만 사용한다.


핵심 원칙

1) 기본값으로 `--isolated=true`를 쓰지 않는다.
2) `docs` workspace는 기본 `http://127.0.0.1:9223`을 사용한다.
3) `mejai` workspace는 기본 `http://127.0.0.1:9224`를 사용한다.
4) MCP는 PID가 아니라 browser URL에 붙는다. PID는 inspect/bind/kill 판단용이다.
5) Codex의 MCP 바인딩은 세션 시작 시 정해지므로, config 변경 후 대상 Codex/LLM CLI를 재시작한다.
6) 종료는 PID 단위 또는 workspace manager의 dry-run 결과를 보고 수행한다. 전체 `pkill`은 사용하지 않는다.


빠른 실행 파일

- workspace별 고정 Chrome + Codex config 자동 갱신:
  - `docs/chrome_split/chrome_devtools_manager.command setup --workspace docs`
  - `docs/chrome_split/chrome_devtools_manager.command setup --workspace mejai`
- 기존 호환 실행 파일(docs workspace setup):
  - `docs/chrome_split/setup_split_chrome_devtools.command`
- 현재 떠 있는 chrome-devtools-mcp/고메모리 node 후보 식별:
  - `docs/chrome_split/audit_chrome_devtools_processes.command`
- isolated 전환 스크립트:
  - deprecated. 전역 `--isolated=true`는 LLM 세션마다 브라우저를 새로 만들 수 있으므로 사용하지 않는다.


workspace별 운영 명령

- docs workspace를 고정 브라우저에 연결:
  - `docs/chrome_split/chrome_devtools_manager.command setup --workspace docs`
  - 9223이 예전 프로필로 이미 점유되어 있으면 `--replace`를 붙인다.
- mejai workspace를 고정 브라우저에 연결:
  - `docs/chrome_split/chrome_devtools_manager.command setup --workspace mejai`
- 브라우저만 미리 켜기:
  - `docs/chrome_split/chrome_devtools_manager.command start --workspace docs`
  - 예전 프로필 브라우저를 workspace 기본 프로필로 갈아끼우려면 `--replace`
- Codex 설정만 해당 workspace 브라우저로 변경:
  - `docs/chrome_split/chrome_devtools_manager.command configure-codex --workspace docs`
- 상태 확인:
  - `docs/chrome_split/chrome_devtools_manager.command status --workspace docs`
  - 관리 중인 Chrome 본체와 그 자식 `Google Chrome Helper (Renderer)`도 같이 표시한다.
- workspace에 붙은 MCP 프로세스 종료 dry-run:
  - `docs/chrome_split/chrome_devtools_manager.command stop --workspace docs`
- workspace에 붙은 MCP 프로세스 종료:
  - `docs/chrome_split/chrome_devtools_manager.command stop --workspace docs --yes`
- 관리 중인 Chrome 브라우저까지 종료:
  - `docs/chrome_split/chrome_devtools_manager.command stop --workspace docs --browser --yes`
  - 이 경우 해당 Chrome의 Helper/Renderer 자식 프로세스도 종료 대상에 포함된다.
- PID 직접 검사:
  - `docs/chrome_split/chrome_devtools_manager.command inspect --pid 12345`
- 이미 켜진 Chrome debug PID를 docs workspace에 바인딩:
  - `docs/chrome_split/chrome_devtools_manager.command bind-pid --workspace docs --pid 12345`
- 해당 workspace에서 Codex를 실행할 때 쓸 override 명령 출력:
  - `docs/chrome_split/chrome_devtools_manager.command launch-command --workspace docs`


기본 포트/프로필

- docs:
  - browser URL: `http://127.0.0.1:9223`
  - profile: `$HOME/.cache/chrome-devtools-workspaces/profiles/docs`
- mejai:
  - browser URL: `http://127.0.0.1:9224`
  - profile: `$HOME/.cache/chrome-devtools-workspaces/profiles/mejai`
- registry:
  - `$HOME/.cache/chrome-devtools-workspaces/registry.json`


표준 절차

1) 정상 macOS Terminal에서 workspace browser를 준비한다.
   - `docs/chrome_split/chrome_devtools_manager.command setup --workspace docs`
2) 대상 Codex/LLM CLI 창만 재시작한다.
3) 재시작 직후 `chrome-devtools.list_pages` 또는 브라우저 검증 작업을 수행한다.
4) 작업 후 MCP 프로세스만 정리하려면 dry-run 후 종료한다.
   - `docs/chrome_split/chrome_devtools_manager.command stop --workspace docs`
   - 결과가 맞으면 `--yes`를 붙인다.


PID를 직접 지정하는 경우

- MCP는 PID에 직접 연결할 수 없다.
- Chrome debug browser PID를 지정하면 manager가 해당 PID의 `--remote-debugging-port`를 읽어 workspace에 바인딩한다.
- 예시:
  - `docs/chrome_split/chrome_devtools_manager.command inspect --pid 73776`
  - `docs/chrome_split/chrome_devtools_manager.command bind-pid --workspace docs --pid 73776`
- `bind-pid` 후에는 Codex config가 해당 browser URL로 바뀌므로 대상 Codex/LLM CLI를 재시작한다.


종료 기준

- 남길 것:
  - 현재 사용 중인 LLM 세션의 부모 체인에 연결된 MCP 프로세스
  - workspace manager가 관리 중인 Chrome debug browser
  - workspace manager가 관리 중인 Chrome debug browser의 `Google Chrome Helper (Renderer)` 자식 프로세스
- 종료 후보:
  - 부모가 `1`이거나 이미 닫은 LLM/터미널에 매달린 고메모리 `node`
  - 부모 Chrome이 종료됐는데 남아 있는 orphan `Google Chrome Helper`
  - Activity Monitor에서 `chrome-devtools-mcp`로 보이고, 현재 workspace manager 상태에 없는 PID
- 종료 순서:
  1) `audit_chrome_devtools_processes.command`로 후보 확인
  2) `chrome_devtools_manager.command inspect --pid <PID>`로 직접 확인
  3) 확실한 PID만 `kill <PID>`
  4) 남아 있을 때만 `kill -9 <PID>`


주의

- `setup_chrome_devtools_isolated.command`는 더 이상 복구 루트가 아니다.
- `~/.codex/config.toml`에 `--isolated=true`가 남아 있으면 `chrome_devtools_manager.command setup --workspace <docs|mejai>`로 `--browser-url` 방식으로 바꾼다.
- 같은 Codex 전역 config를 여러 workspace가 동시에 공유하므로, 동시 실행이 필요하면 `launch-command`가 출력하는 `codex -c ...` override 방식으로 workspace별 CLI를 띄운다.
